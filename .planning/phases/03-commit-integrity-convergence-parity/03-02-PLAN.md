no seam logic, no new validation. It exists so the four seam-wiring plans in later waves can
yield the right shapes without each re-editing `types.ts`.

the later plans free of merge-shaped conflict and keeps the `kind ↔ Disposition` exhaustive
switch honest.
Output: widened `IngestResult` union + disposition map, the `SelfEvicted` named outcome, a new
`src/engine/state-notifications.ts` (type + bounded ledger), and the client-side mirror.
</objective>

Create `src/engine/state-notifications.ts` with the module header `/** @module @category Engine */`.

Export a `StateNotification` discriminated union on `kind`, every variant carrying `commitDigest: Uint8Array` (D-10):

- `epochAdvanced` with `from: number` and `to: number`
- `memberAdded` with `pubkey: string`
- `memberRemoved` with `pubkey: string` and optional `actor?: string`
- `componentChanged` with `componentId: number`
- `selfRemoved` (no extra fields beyond `commitDigest`)
- `branchRecovered` with `forkEpoch: number`

Give the union a doc comment citing `convergence.md` "Applying the selected branch" and stating that the shape is implementation-defined while `commit_digest` attribution is the conformance requirement.

Export `StateNotificationLedger` — a structural sibling of `DeliveredPayloadLedger`, NOT generic over an envelope type. Private `#entries` array of `{ digest: string; epoch: number; notifications: StateNotification[] }` using native `#` fields. Methods:

- `get size(): number`
- `record(digest: Uint8Array, epoch: number, notifications: StateNotification[]): void` — stores `bytesToHex(digest)` (import `bytesToHex` from `@noble/hashes/utils.js`). A record with an empty notification array is skipped so the ledger stays bounded.
- `invalidatedByRewind(forkEpoch: number, canonicalDigests: ReadonlySet<string>): StateNotification[]` — removes and returns notifications from entries whose `epoch > forkEpoch` and whose hex digest is NOT in `canonicalDigests`, keeping everything else. Same partition-into-kept/invalidated shape as the template.
- `pruneBelow(epoch: number): void` — drops entries with `epoch < epoch`.

Key difference from the template, and the reason to state it in the class doc comment: this ledger is keyed by hex `commitDigest` (the commit's identity) rather than by the delivery state's confirmation tag, because CONV-03 attributes notifications to the commit that produced them.

Add `export * from "./state-notifications.js";` to `src/engine/index.ts`, placed after the `./types.js` line.

Create `src/engine/__tests__/state-notifications.test.ts` mirroring `delivered-payloads.test.ts`. Cases:

- `record` increments `size`; recording an empty notification array does not
- `invalidatedByRewind` returns notifications recorded above `forkEpoch` whose digest is absent from `canonicalDigests`, and removes them from the ledger (`size` drops)
- `invalidatedByRewind` retains entries at or below `forkEpoch` (shared history) even when their digest is absent from `canonicalDigests`
- `invalidatedByRewind` retains entries above `forkEpoch` whose digest IS in `canonicalDigests` (the winning branch's own notifications are not withdrawn)
- `invalidatedByRewind` returns an empty array on an empty ledger
- `pruneBelow` drops entries strictly below the given epoch and keeps entries at that epoch
- a `selfRemoved` notification recorded above the fork epoch on a losing branch is returned by `invalidatedByRewind` (this is the CONV-03 marker-clear trigger; assert the returned array contains a `kind === "selfRemoved"` entry)
  </action>
