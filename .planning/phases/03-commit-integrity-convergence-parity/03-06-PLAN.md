<objective>
Close CONV-02: turn removal from a fire-once side effect of applying one commit into a
state-derived, restart-durable obligation. Add the `SelfEvicted` classification for later input,
the engine-level outbound block, the persisted removed-inactive marker, and load-time realization.
Also land the folded `groupsmanager-rejectedevents-dos` todo, which is the remaining client-layer
cleanup from Phase 2's review.

Purpose: today marmot-ts detects the `removedFromGroup` tombstone only on the commit that
produces it. A process that exits between apply and notification never tells the app; later input
for the group is peeled and decrypted for nothing; and a fresh `send()` after restart is not
blocked. Criterion 3 requires all three.
Output: the `self-evicted` short-circuit, the D-14 throw, `removedMarkerStore` + realization in
`MarmotGroup`, and the `rejectedEvents` drain fix.
</objective>

Client side (`src/client/group/marmot-group.ts`):

1. Add `removedMarkerStore?: GenericKeyValueStore<boolean>;` to `MarmotGroupOptions`, documented as the persisted removed-inactive marker (D-12) — a sibling store keyed by the same group-id hex as `store`, deliberately NOT a field grafted onto the serialized `ClientState`, so the marker is readable and clearable without a full state deserialize and `ClientState` stays exactly what ts-mls produces. 2. Add a private async `#realizeRemovalIfNeeded(): Promise<void>` implementing the shared obligation: if `this.state.groupActiveState.kind !== "removedFromGroup"` return; read the marker for this group id; if already set, return; otherwise set the marker to `true`, call `#rejectQueuedOutbound` with the existing message, and `emit("removed", this)`. 4. Call `#realizeRemovalIfNeeded()` from the existing `result.kind === "removed"` branch in the ingest handler, replacing the inline `#rejectQueuedOutbound` + `emit("removed")` pair with the single idempotent call so the two paths cannot diverge.

Add it here so 03-07 does not have to reopen the marker plumbing, and mark it with a comment naming CONV-03 as its caller.
6. If `GroupsManager` (or any other loader) constructs `MarmotGroup` by a path that bypasses `fromClientState`, thread `removedMarkerStore` through and realize there too — find every construction site before deciding.
