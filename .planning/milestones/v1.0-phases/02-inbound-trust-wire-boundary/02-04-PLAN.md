<objective>
Close the three confirmed defects in 02-VERIFICATION.md that block Phase 2's goal — a
conformant peer must not silently accept malformed input or forge trust in unverified
fields:

1. GAP 1 (WIRE-02 / SC3): 1059 `p`-tag cardinality is declared in `TAG_CARDINALITY` but
   never enforced in `InviteManager.ingestEvent`.
2. GAP 2 (SEC-01 / SC1 / WR-01): the 445 drain adds every fresh event's id to the dedup
   `seen` set BEFORE verification, so a corrupted same-id forgery censors the genuine event.
3. GAP 3 (WIRE-02 self-consistency / WR-02): `createWelcomeRumor` allows duplicate relay
   URLs that its own strict consumer (`getWelcome`) rejects, producing an un-decodable invite.

Purpose: finish the WIRE-02 cardinality contract for 1059, restore the "no unverified-field
trust" guarantee for legitimate 445 delivery, and make the 444 producer conform to the same
#236 cardinality its own consumer enforces.
Output: a `p`-tag gate on `ingestEvent`, a dedup-after-verify reordering in `#connectGroup`,
and a duplicate-relay rejection in `createWelcomeRumor` — each shipped with its failing-then-
passing test.
</objective>
