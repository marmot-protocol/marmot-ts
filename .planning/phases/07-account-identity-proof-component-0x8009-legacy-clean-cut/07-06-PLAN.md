Planning-time facts verified on 2026-09-14 (do not re-derive):

- MDK `leaf_app_components_extension` builds the leaf dictionary as: 0x0001 = the sorted advertised set (supported ids plus 0x0001, plus 0x8009 when a proof is present), 0x0002 = empty components list, 0x8009 = the proof. MDK `CURRENT_PROFILE_REQUIRED_APP_COMPONENTS = [0x8003, 0x8009]` and `CURRENT_PROFILE_REQUIRED_GROUP_CONTEXT_EXTENSIONS = [0x0006]`.
- `refs/marmot/transports/nostr.md`: "The `app_components` tag MUST include the value `0x8009`"; "The current profile does not require legacy extension type `0xf2f1` in `mls_extensions`". `createKeyPackageEvent` derives the app_components tag from `SUPPORTED_APP_COMPONENT_IDS`, and derives mls_extensions from the KeyPackage's own leaf capabilities (no test pins 0xf2f1 there).
- The pinned MDK tag fixture `src/__tests__/fixtures/key-package-tags-rust.json` (mdk_sha `dbf45c83`) predates the 0x8009 tag rule. Its app_components tag is `0x8001 0x8003 0x8004 0x8005 0x8006 0x8007 0x8008 0x800c`.
- The current leaf dictionary hex pinned in dictionary.test.ts is `00061b1a0001131200018001800380048005800680078008800c00020100` (hand-encoded `[0x00, extensionType, extensionData.length, ...extensionData]`). With 0x8009 added to the list and only the 0x0001 and 0x0002 entries projected, the same hand encoding is `00061d1c00011514000180018003800480058006800780088009800c00020100`. The real dictionary additionally carries a third entry: 0x8009, 104 bytes, 2-byte varint length prefix. Proof bytes are nondeterministic (created_at, BIP-340 aux randomness), so byte pins MUST use this projection (PITFALLS 14).
- `src/core/__tests__/group.test.ts` line 59 pins `getAppComponents(clientState.groupContext.extensions)` to `[0x8001, 0x8003, 0x8004, 0x800c]`; with D-05 it becomes `[0x8001, 0x8003, 0x8004, 0x8009, 0x800c]`.
- Conformance runners (`named-vectors.test.ts`, `extended.spec.ts`) compare GroupContext hashes across clients, not against pinned values, so adding 0x8009 to the required list needs no conformance fixture change.
- `createAdminCommitPolicyCallback` receives `proposal.add.keyPackage` (a full ts-mls KeyPackage in production).
- `joinFromWelcome` in `src/client/groups-manager.ts` currently runs the legacy whole-tree verifier after the candidate loop and before `adoptClientState`. `GroupRegistry.load` and hydration have no proof check and must stay that way (D-10).
- `ClientState.groupContext.cipherSuite` is the group's negotiated ciphersuite id.
- After plans 07-03, 07-04, and 07-05, the only `generateKeyPackage` call without a signer is the proof-less case in `invite-user.test.ts`, which Task 2 rewrites. `pnpm exec tsc -p tsconfig.json --noEmit` is the definitive gate once `signer` is required.
