## Pattern Assignments

### `src/core/components/group-lifecycle.ts` (new codec)

**Analog:** `src/core/components/message-retention.ts`

Copy the pure named-export codec shape, `BinaryReader`/`BinaryWriter`, exact-length validation via `reader.end()`, and colocated constants. The new type should be the established enum-like object plus a derived value union, e.g. `groupLifecycleV1States.active/disbanded`, not a TypeScript enum. The wire is exactly one byte (`0x00`, `0x01`); reject unknown values and trailing bytes.

```ts
  const reader = new BinaryReader(data);
  // decode and validate
  reader.end();
  return ids;
}
```

### `src/core/components/integrity.ts`

**Analog:** `validateCommitLegality` composing generic integrity and admin/leaf coupling (`src/core/components/integrity.ts:28-43,65-86,110-169`).

Add a typed lifecycle/disband violation and a pure validator invoked by the existing shared legality adapter so outbound staging, inbound processing, and convergence replay cannot disagree. Validate against parent/resulting state plus the actual committed proposal list. Required checks include absorbing presence/removal rules, `active -> disbanded`, inline-only update, admin authorization, exact committer-only resulting admin policy, removal of every other parent leaf (including sibling leaves for the same account), and rejection of every unrelated proposal kind. Preserve the current non-throwing result convention:

```ts
export interface CommitIntegrityViolation {
  reason: CommitIntegrityViolationReason;
  detail: string;
}
```

Use the existing parent-derived protected-set rule (`integrity.ts:129-143`) to reject removal of required lifecycle state. Extend `CommitIntegrityViolationReason` and `RejectedIngestResult.reason` rather than adding seam-specific throws.

### `src/engine/state-notifications.ts`

**Analog:** the pure before/after notification diff and commit-digest ledger (`src/engine/state-notifications.ts:16-47,64-125,168-255`).

Notification remains commit-digest attributed. Unlike ordinary effects, canonical disband must not be withdrawable after terminalization.

### `src/engine/group-engine.ts` and `ingest.ts`

**Analogs:** immutable pass admission (`group-engine.ts:537-548`), scheduling (`1155-1230,1578-1612`), removed guard (`551-562`), and recovery apply (`1934-1950,1959-2102`).

The forced-disband signal must be produced only after full parent-relative validation. On admission:

```ts
this.#convergencePass = this.#convergencePass
  ? refreshConvergencePass(this.#convergencePass, nowMs)
  : openConvergencePass(nowMs, maxDurationMs, generation);
```

Do **not** call the normal refresh path if it would alter semantics beyond opening/joining the pass: D-06 says forced admission cannot restart the convergence deadline, resnapshot pass base epoch, or influence scoring. Current `refreshConvergencePass` preserves `generation/openedAtMs/deadlineMs` but moves `lastRelevantInputMs`; planner should make the forced path explicit and add a regression assertion for every field.

The direct linear apply in `ingest.ts:731-784` must retain a valid disband commit as candidate material and route through canonical selection rather than calling `setState`/returning `processed`. After selection, transition `Stable -> Recovering` on the linear exception and `Recovering -> Disbanded` only when the winner ends disbanded. Then stop schedulers, pooling, convergence, maintenance, and app delivery.

Post-terminal inbound should mirror the pre-decryption short circuit at `ingest.ts:331-345`: yield one inactive skip per envelope without invoking the peeler or changing any pass state.

### `src/engine/fork-recovery.ts`

**Analog:** ordinary candidate construction and unchanged selection (`fork-recovery.ts:374-390,431-560`).

Carry “candidate ends disbanded” metadata only as an application outcome. Continue to call `selectCanonicalBranch(currentTipEpoch, branches, policy)` unchanged and preserve the existing score/tie-break order. A one-candidate linear disband pass must still produce a selectable candidate; current `resolveFork` returns `skip` when canonical `ours` is empty (`:453-462`), so the planner must account for this linear exception rather than assuming fork-only recovery already handles it.

### `src/client/session/group-session.ts`

**Analog:** state/tree durability and terminal wrapper ordering (`group-session.ts:332-347,523-600`).

Persist the terminal marker/tombstone before exposing any public notification. Current ordering is the template:

```ts
await this.save(true);
await this.#wrapperLedger?.record(mapped.event.id, outcome);
```

Do not graft unversioned bytes onto `SerializedClientState`; D-01 requires an explicitly versioned sibling persisted record or a versioned envelope with backward decoding. Older stored groups must decode active/live. The terminal record must be authoritative on load even if live MLS bytes/history remain from a torn prior write.

### `src/client/group/marmot-group.ts` and `group-registry.ts`

**Analog:** durable, exactly-once removal realization (`marmot-group.ts:161-174,234-264,320-331,845-905`) plus safe hydration activation (`group-registry.ts:151-195,266-304`).

Expose status/view and one `groupDisbanded` public event. Follow the ordering: attach registry/public listeners, reconcile persisted state, durably realize terminal state, then emit. Reject and drain every queued outbound promise with a typed terminal reason. Do not copy `#clearRemovalMarker` behavior: a disband marker is absorbing and never cleared by reconvergence or reload. Loading a disbanded group should construct a read-only authenticated tombstone without restarting fork rehydration/reconvergence or routing.

The Applesauce-specific constraint here is modest: continue importing Nostr types/signers from public package paths (never `dist/`) and keep event publication/session state within the existing single client ownership flow. No new `EventStore` is warranted.

## Shared Patterns

### Named ESM exports and binary portability

All new relative imports use emitted `.js`; all exports are named; protocol bytes remain `Uint8Array`; no `Buffer` or runtime-specific persistence API.

### Parent-relative validation

**Source:** `src/core/components/integrity.ts:102-108,129-169`

Derive required components, admin authorization, committer leaf, and removal set from the candidate parent. Validate the resulting dictionary/roster before an edge is created. Never infer parentage from Nostr metadata.

### Publish-before-apply

**Source:** `src/engine/group-engine.ts:703-745,1051-1109`

Local disband creation must stage and publish before admission; publication alone does not terminalize. A durable local `Disbanding` gate, if implemented in this phase, survives publish failure and a losing branch and regenerates against the selected active state.

### Durable-before-observable

**Source:** `src/client/session/group-session.ts:581-600`; `src/client/group/marmot-group.ts:845-905`

Canonical terminal state/marker and retained authenticated tombstone must be durable before `groupDisbanded` reaches listeners. Event dispatch must be idempotent and listener failures must not undo persistence.

### No disband scoring rule

**Source:** `src/engine/fork-recovery.ts:509-540`

Do not add lifecycle state to `BranchCandidate`, `scoreBranch`, `compareBranchScores`, or tie-breaks except as post-selection outcome metadata.
