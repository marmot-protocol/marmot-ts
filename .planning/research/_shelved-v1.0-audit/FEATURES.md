# Feature Research

**Domain:** Marmot (MLS over Nostr) single-device TypeScript client library — spec conformance audit surface
**Researched:** 2026-07-01
**Confidence:** HIGH (sources: darkmatter spec at `c9d63de`, `SPEC_GAP_REVIEW.md` 2026-06-19, `ts` codebase inspection)

---

## Scope of this document

This document maps every spec area in `darkmatter/spec/` to one of three categories for the Phase 1 audit:

- **Table stakes** — required for single-device wire interop with the Rust darkmatter reference; must be closed this milestone.
- **Deferred** — optional or not-yet-normative features; catalog only, do not build this milestone.
- **Anti-features** — deliberately not built; document as unsupported.

Each entry records the spec source, current TS status, implementation complexity, and gap likelihood. Status uses these shorthands:

- `DONE` — confirmed shipped (baseline + M1–M8 + m1/m4/m5/m6)
- `PARTIAL` — partially implemented; specific gap noted
- `OPEN` — known gap from SPEC_GAP_REVIEW (M9/m7/m8/m9/m3)
- `AUDIT` — not confirmed either way; needs Phase 1 inspection to call

## Feature Dependencies

```
account-identity-proof-v1 (0xf2f1)
    └──required-by──> every KeyPackage and member LeafNode
    └──required-by──> admin-policy-v1 (active-admin = listed key + current leaf)

admin-policy-v1 (0x8003)
    └──gates──> profile updates, routing updates, media policy updates, invite, remove
    └──required-by──> Welcome join validation (author must be active admin)

nostr-routing-v1 (0x8004)
    └──required-by──> Nostr transport (all kind 445 delivery)
    └──gates──> routing rotation subscription

encrypted-media-v1 (0x8008) policy component
    └──required-by──> encrypted-media feature (media messages in app groups)
    └──gates──> source-epoch media secret selection (M9 dependency)

message-retention-v1 (0x8005)
    └──drives──> NIP-40 expiration tag on kind 445 app messages (likely gap)

source-epoch media secret (M9)
    └──depends-on──> retained per-epoch exporter secrets in engine/retained-store
    └──depends-on──> engine plumbing to GroupMediaService
```

### Dependency Notes

- **M9 depends on retained-history store:** `deriveMediaEncryptionKey` already takes a `ClientState` parameter for the source epoch, but `GroupMediaService` currently passes the live tip state. Closing M9 requires plumbing retained exporter secrets from `RetainedHistoryStore` through the engine into the media service for each inbound media message.
- **NIP-40 expiration depends on message-retention-v1:** The codec is already done. The expiration tag emit is a send-path gap in `GroupRuntime` — when message-retention is enabled and the commit is an app message, the runtime must compute `inner_created_at + disappearing_message_secs` and attach the NIP-40 expiration tag.
- **Routing rotation subscription depends on nostr-routing-v1 history:** After a routing update commit is applied, the prior `nostr_group_id` must be retained in subscription state for the duration of `app_payload_past_epoch_limit` epochs.
