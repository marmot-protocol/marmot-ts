then gate the 445 and 1059 inbound entry points on verify-before-trust and migrate the 444
welcome-rumor required-tag reads to the strict getters.

Purpose: Close SEC-01 for the 445 group-message and 1059 gift-wrap paths, and WIRE-02 for
445 `h` and 444 `e`/`relays`, using the primitives from plan 02-01. This is the
verify-before-trust wiring for the two entry points that need no KeyPackage-lifetime logic.
Output: threaded `verifyEvent` option, a `rejected` event on GroupsManager and InviteManager,
and strict-getter 444 decoding.
</objective>

<threat_model>

## Trust Boundaries

| Boundary                    | Description                                                                                                                   |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| relay/MITM → 445 drain      | A fabricated or tampered kind-445 event could be handed to the engine if trusted before verify                                |
| relay/MITM → 1059 inbox     | The outer gift wrap is unverified by applesauce's unlockGiftWrap (seal-only); an attacker could inject a forged 1059 envelope |
| relay/MITM → 444 rumor tags | Duplicate/empty `e`/`relays` could smuggle a second value past a first-match reader                                           |

## STRIDE Threat Register

| Threat ID       | Category          | Component                                | Severity | Disposition     | Mitigation Plan                                                                                                                                                    |
| --------------- | ----------------- | ---------------------------------------- | -------- | --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| T-02-01         | Spoofing          | groups-manager #connectGroup drain (445) | high     | mitigate        | Run injected VerifyEventMethod as the first gate before group.ingest; reject invalid id/sig with emit('rejected', groupId, event, 'invalid-signature') (SEC-01)    |
| T-02-02         | Spoofing          | invite-manager.ingestEvent (1059)        | high     | mitigate        | Verify the OUTER kind-1059 event before store/decrypt, closing the unlockGiftWrap seal-only gap; reject with emit('rejected', event, 'invalid-signature') (SEC-01) |
| T-02-03         | Tampering         | 445 `h` / 444 `e`,`relays` reads         | high     | mitigate        | getSingletonTagValue/getListTag reject repeated/empty/duplicate required tags with reason 'tag-cardinality' instead of first-match (WIRE-02)                       |
| T-02-04         | Denial of Service | 444 rumor decode with malformed tags     | medium   | mitigate        | Strict getters return undefined → typed reject; getWelcome does not let a malformed tag throw an unhandled deep-decode error                                       |
| T-02-05         | Tampering         | unsigned 444 rumor mistakenly verified   | medium   | accept→mitigate | Explicitly never pass the rumor through VerifyEventMethod; only the signed 1059/seal are verified (RESEARCH Pitfall 4)                                             |
| </threat_model> |
