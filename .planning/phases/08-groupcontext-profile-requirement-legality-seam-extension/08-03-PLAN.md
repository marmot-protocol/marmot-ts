<objective>
Define and enforce what happens to stored groups outside the current `0x8009` profile (D-11, D-12). They load (never
throwing inside `loadAll`), are marked with a typed `profileSupport` flag, stay listable and `destroy()`-able, and
have ALL traffic refused. Outbound sends throw `UnsupportedGroupProfileError`. Inbound envelopes are skipped as
`unsupported-profile` before any decrypt. Nothing is deleted or published automatically.

Purpose: completes the phase goal "every group requires `0x8009`" for groups persisted before the cut. It supersedes
Phase 7 D-10 ("load untouched"), where an old legacy/mixed group could still exchange traffic with members this
client never validated. Commit-legality seams would reject every commit for such a group anyway (plan 08-01 D-01a
parent check), but application messages and proposals would still flow. This plan closes that.
Output: engine and session gates, `profileSupport` on engine/session/`MarmotGroup`, a registry activation guard,
tests, migration docs, and changeset.
</objective>
