<objective>
Add the founding-Add send seam to the engine: a new `SendIntent`/`SendResult` pair (D-02) whose case reuses
`case "commit"`'s staging skeleton minus the envelope wrap, passes the identical legality gate (FOUND-02), and
hands back a `PendingState` the caller confirms through the unmodified `confirmPublished()` (D-01).

Purpose: this is the only plan that touches the engine. Everything downstream (the client orchestration in
10-03) depends on these two type variants existing, so it ships first and alone. Adding a `SendResult` member
without an `envelope` field is a compile-blocking change to `send()`'s audit-outcome block — that fix is an
explicit task here, not a surprise for a later plan.
Output: `foundingAdd` intent, `foundingGroupCreated` result, the new `#sendInner` case, the per-kind audit
branch, two new audit-kind arms, and a dedicated engine test suite.
</objective>

- `PendingState.kind` for the founding Add is the existing literal `"commit"` (RESEARCH Assumption A1). This

  `confirmPublished()`'s branch condition.

  carries Adds, so a missing Welcome is an engine-level error, not an absent field.
