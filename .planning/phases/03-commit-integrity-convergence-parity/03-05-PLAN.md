`#treeResolution` is the third route by which a commit becomes canonical state: it adopts a winner chain read straight out of the persisted history tree with no replay, so a violating edge recorded by a pre-upgrade build could still be adopted. D-04/D-09 require all three routes to agree.

Add a validation pass over the assembled `winnerChain` inside `#treeResolution`, after the chain is built and before it is returned:

For each `link` in `winnerChain`, replay the link to recover the commit's own proposals: build a capture wrapper with `withCapturedProposals(this.#createAdminVerificationCallback())`, call `take()` to clear, then `processMessage({ context: { cipherSuite: this.ciphersuite, authService: marmotAuthService, externalPsks: {} }, state: link.parent, message: link.message, callback })`, then `take()` for the proposals. Wrap the call in try/catch.

Fail closed — return `undefined` from `#treeResolution` (which makes `#reconvergeFromTree` a no-op, leaving the current tip in place) when ANY of the following holds for any link:

- `processMessage` threw
- the result is not `kind: "newState"`, or `actionTaken === "reject"`
- the replayed `newState.confirmationTag` is not byte-equal to the stored `link.child.confirmationTag` (the stored snapshot disagrees with the commit bytes)
- `validateCommitLegality({ parentState: link.parent, resultingState: link.child, proposals: capturedProposals })` returns a violation

Log each abandonment through `this.#log()` with the link's child tag prefix and the violation reason so an operator can see why a persisted branch became unselectable. Update `#treeResolution`'s doc comment: it now replays each link to re-derive the commit's proposals and re-validate legality before adoption, which is what makes D-04's "no grandfathering" hold for trees written by older builds; the accepted consequence is that such a branch becomes unselectable and, if it was the only candidate, the group stays on its current tip.

Add two cases to `src/engine/__tests__/send-commit-legality.test.ts`:

- a tree-fed re-convergence whose winner chain is legal still switches branches (assert `state.confirmationTag` moved to the winner tip after `reconvergeFromHistory()`)
- a tree-fed re-convergence whose winner chain contains a link that fails `validateCommitLegality` does NOT switch (assert `state.confirmationTag` is unchanged after `reconvergeFromHistory()` and the lifecycle is still `stable`)
  </action>
