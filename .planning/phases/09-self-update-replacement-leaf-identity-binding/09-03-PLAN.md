<objective>
Close UPD-04, the standalone-Update admission gap Phase 8 explicitly deferred (08 D-10). Add one pure core validator
for the Update branch and call it from both admission seams, so an Update proposal's `0x8009` proof and its account
identity are checked before the proposal is queued rather than only when a later commit bundles it.

Purpose: `SendIntent` accepts `{ kind: "proposal"; proposal: Proposal }` for any raw proposal, and neither the
existing Add branch nor `validatePreApplyProposals` inspects Updates — so a locally built standalone Update currently
bypasses every proof and identity check. MDK's own rationale applies: a syntactically valid MLS proposal must not sit
pending until a later Commit discovers that its leaf proof or profile is invalid.
Output: `validateUpdateProposalAccountIdentityProofs`, the two seam gates, and an admission test suite mirroring the
standalone Add suite.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| remote member → local proposal queue | A standalone Update proposal from any member is staged into `unappliedProposals` and later bundled by reference into a commit |
| local application code → engine send | `SendIntent` accepts an arbitrary raw `Proposal`, including an Update the application constructed itself |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-09-14 | Spoofing | standalone Update sender | high | mitigate | The sender leaf is resolved through `getCredentialFromLeafIndex` and the replacement leaf's credential must equal it; an unresolvable sender is rejected outright (D-10) |
| T-09-15 | Elevation of Privilege | identity swap via standalone Update | high | mitigate | Identity equality is enforced pre-apply at both seams with the same `member-identity-changed` literal the commit-time path uses, so the two entry points cannot diverge |
| T-09-16 | Tampering | queued-proposal poisoning | high | mitigate | A bad Update is refused before it reaches `unappliedProposals`, so it can never be bundled by reference into a later commit; the commit-time tree diff remains the backstop |
| T-09-17 | Elevation of Privilege | undecodable admin policy as a bypass | medium | mitigate | The fallback callback that rejects all commits but admits proposals now runs the same Update gate, closing the asymmetry |
| T-09-18 | Denial of Service | false-positive rejection of honest self-updates | high | mitigate | An explicit no-false-positive test stages an honest inbound Update, and a further test proves `send({kind:"selfUpdate"})` is unaffected — joining.md has every new member self-update immediately, so a false positive here would break joins |
| T-09-19 | Information Disclosure | admission violation details | low | mitigate | Every `detail` names only the positional proposal index and a reason literal; `leafIndex` is omitted because the proposal is not applied |
| T-09-20 | Tampering | npm/pip/cargo installs | high | accept | This plan adds no dependency; `package.json` is not in `files_modified`. No package-legitimacy checkpoint is required |
</threat_model>
