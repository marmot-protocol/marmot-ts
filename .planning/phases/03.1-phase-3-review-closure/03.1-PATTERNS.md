## Shared Patterns

### Irreversible Confirmation Boundary

**Source:** `src/engine/group-engine.ts:930-974`
**Apply to:** runtime and auto-commit changes

```typescript
this.#setState(pending.newState);
this.#recordCommitNode(
  pending.parentState,
  pending.commitMessage,
  pending.newState,
);
const notifications = deriveStateNotifications({
  parentState: pending.parentState,
  resultingState: pending.newState,
  commitDigest: digest,
});
this.#stateNotifications.record(digest, toEpoch, notifications);
return notifications;
```

After this call returns, state and ledger are advanced. Persistence/Welcome failures are ancillary
outcomes, never grounds to erase the confirmed notifications or call `publishFailed`.

### Single-Flight Async Work

**Source:** `src/client/group/group-media-service.ts:129-160`
**Apply to:** removal realization

Check for an in-flight Promise, create and store the new Promise before awaiting it, then clear it
in `finally`. For removal, clearing after rejection permits retry; the durable marker prevents
re-emission after successful completion.

### Event Listener Ownership

**Source:** `src/client/group-registry.ts:264-280`
**Apply to:** every loaded/adopted group path

The registry owns caching and forwarding listeners. Any state-derived operation capable of emitting
`removed` must run after `group.on("removed", forwarder)` and before `loaded` is emitted.

### Error and Result Conventions

Pre-confirm network/validation failure throws and rolls back. Expected post-confirm partial outcomes
use named discriminated unions. Tests use `await expect(...).rejects` only for the former and inspect
typed statuses for the latter. No new dependency, mutex primitive, runtime-specific API, default
export, or extensionless relative import is appropriate.
