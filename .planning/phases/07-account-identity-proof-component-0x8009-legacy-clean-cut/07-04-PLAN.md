Migration rules (identical in plans 07-03, 07-04, 07-05; each plan owns a disjoint file set):

1. Every `generateKeyPackage({ ... })` call in an owned file passes `signer: X.signer`, where `X` is a
   `PrivateKeyAccount` whose `pubkey` equals the credential identity passed as `credential`.
2. Obtain `X` from an existing `PrivateKeyAccount` already in scope when there is one. Otherwise use
   `testAccount(slot)` imported from the shared helper, with a relative path ending in `/__tests__/helpers/test-accounts.js`.
3. When a credential used a literal test pubkey (for example `"a".repeat(64)`), replace that literal with the derived
   `pubkey` of one account held in a variable, and use that same variable everywhere the literal meant the same identity.
4. Preserve relative order. Within a file, assign slots in the same ascending order as the literals sort. Use this
   default mapping:
   - `"2".repeat(64)` → slot 0
   - `"3".repeat(64)` → slot 1
   - `"4".repeat(64)` → slot 2
   - `"884704bd421671e01c13f854d2ce23ce2a5bfe9562f4f297ad2bc921ba30c3a6"` → slot 5
   - `"a".repeat(64)` → slot 6
   - `"d".repeat(64)` → slot 9
   - `"e".repeat(64)` → slot 11
   Pick any other free slots in ascending order.
5. A literal pubkey that never backs a KeyPackage may stay literal. If ordering then breaks, migrate it too.
6. A local setup helper that takes a pubkey string and generates a KeyPackage inside changes minimally. It takes the
   account, or the pubkey plus signer.
7. Never weaken, delete, or re-baseline an assertion to make a test pass. If an assertion encoded a literal pubkey value
   rather than identity equality, update it to the derived value and list it in the SUMMARY.
8. No production file changes. Hand-built legacy-proof leaves that do not call `generateKeyPackage` are out of scope; for
   example the forged-proof admin-policy test in marmot-group.test.ts is rewritten by plan 07-07.

Signer gate (used in acceptance criteria). This Node one-liner prints every `generateKeyPackage({...})` call whose
options object lacks `signer` and exits 1 if any exist:

`node -e 'const fs=require("fs");let bad=0;for(const f of process.argv.slice(1)){const s=fs.readFileSync(f,"utf8");for(const m of s.matchAll(/generateKeyPackage\(\s*\{[\s\S]*?\}\s*\)/g)){if(!/\bsigner\b/.test(m[0])){bad++;console.log(f+": "+m[0].replace(/\s+/g," ").slice(0,100))}}}process.exit(bad?1:0)' FILES...`

- dictionary.test.ts "matches the MDK leaf dictionary bytes through a real KeyPackage" and safe-aad-parity.test.ts extract only the `app_data_dictionary` extension. In the current format the proof is a separate extension, so a different credential identity does not change the pinned hex.
