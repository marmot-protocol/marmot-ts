<objective>
Migrate `src/core/account-identity-proof.ts` from account-identity-proof **v1 → v2** so the
64-byte Schnorr signature signs the canonical, unpublished **kind-450 Nostr event id** (per
D-v2-wire in 01-CONTEXT.md and PROOF-V2.md), bump the version byte `1 → 2`, add the external
Nostr-signer parity builders, verify per-ciphersuite `signature_scheme` decimals against the
Rust reference, and replace the module's own v1 test vectors with v2. This is the headline
interop-breaker (PROOF-01), migrated in isolation inside the one core module + its colocated test.

Purpose: close the byte-for-byte interop break with the MDK Rust reference (`marmotkit-v0.9.4`,
mdk #755). Rust is authoritative for the v2 wire format; spec `refs/marmot` still documents only v1.
Output: a v2-only account-identity-proof core with an external-signer path and green colocated tests.

<threat_model>

## Trust Boundaries

| Boundary                       | Description                                                                                                                                                     |
| ------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| account key → MLS leaf         | The Nostr account key signs a proof binding its identity to a per-leaf MLS signature key; a verifier trusts the credential identity only if this proof verifies |
| decoded proof bytes → verifier | Attacker-controlled extension bytes from an untrusted leaf/KeyPackage cross into `decodeAccountIdentityProof`/`verifyLeafAccountIdentityProof`                  |

## STRIDE Threat Register

| Threat ID       | Category               | Component                                     | Severity | Disposition | Mitigation Plan                                                                                                                                                                                       |
| --------------- | ---------------------- | --------------------------------------------- | -------- | ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-01-01         | Spoofing               | `verifyLeafAccountIdentityProof`              | high     | mitigate    | Signature must verify over the exact canonical kind-450 event id (account identity as event pubkey); binding checks (identity, mls key, ciphersuite, signature_scheme) all enforced before acceptance |
| T-01-02         | Tampering              | `accountIdentityProofSigningDigest` tag order | high     | mitigate    | Six tags built in exact Rust order/format via getEventHash; a wrong-order/format digest cannot cross-verify with a conformant peer — locked by the independent-reconstruction test                    |
| T-01-03         | Tampering              | `decodeAccountIdentityProof` version gate     | high     | mitigate    | Only version byte 2 accepted; v1 (byte 1) and any other value rejected; trailing-byte rejection retained                                                                                              |
| T-01-04         | Information disclosure | kind-450 signing template                     | low      | accept      | Event is a local signing template only, never published/relayed (registries.md); no secret material is placed in it                                                                                   |
| </threat_model> |
