<objective>
Close CONV-03: attribute every group-state-change notification to the `commit_digest` that
produced it, and withdraw those notifications — including clearing the removal marker — when a
rewind supersedes that commit. This mirrors `DeliveredPayloadLedger`, which the spec explicitly
names as the counterpart of this rule.

Purpose: Marmot v2 delivers eagerly. An app that was told "Bob was removed" or "you were removed"
on a branch a later convergence pass abandons must be told to undo exactly that. Typed,
digest-attributed notifications are what make that undo expressible.
Output: notification derivation, ledger wiring at the rewind path, the `stateInvalidated` result,
and marker clearing on supersession.
</objective>

  <action>
Add to `src/engine/state-notifications.ts` a pure derivation function:

`export function deriveStateNotifications(args: { parentState: ClientState; resultingState: ClientState; commitDigest: Uint8Array }): StateNotification[]`

It performs a before/after diff and returns notifications in a stable order (emit in the order listed below so two runs over the same commit produce byte-identical output):

1. `epochAdvanced` when `Number(resultingState.groupContext.epoch) !== Number(parentState.groupContext.epoch)`, carrying `from` and `to`
2. `memberAdded` for each hex pubkey in `getGroupMembers(resultingState)` absent from `getGroupMembers(parentState)`, sorted ascending by pubkey
3. `memberRemoved` for each hex pubkey in `getGroupMembers(parentState)` absent from the resulting set, sorted ascending by pubkey. Leave `actor` undefined here — the committer is known to the seam, not to this pure diff; a seam may fill it in later
4. `componentChanged` for each component id whose dictionary bytes differ between the two states (added, rewritten, or removed), read through ts-mls `getAppDataDictionary` so unknown ids are covered, sorted ascending by id
5. `selfRemoved` when `resultingState.groupActiveState.kind === "removedFromGroup"` and the parent's was not

Every returned notification carries `args.commitDigest`. The function performs no I/O and takes no ledger — it is a pure diff, matching MDK's `group_state_changes.rs` split.

In `src/engine/ingest.ts` commit branch, after the legality gate passes and `ctx.setState(result.newState)` has run:

- Compute the commit's digest once (reuse the existing `commitDigest` computation in this file over the encoded MLS message rather than adding a second hashing path).
- Call `deriveStateNotifications({ parentState, resultingState: result.newState, commitDigest })`.
- Attach the result to the yielded `processed` result as `notifications`.
- On the `removedFromGroup` branch, use the derived list instead of the hand-built single-element array plan 03-06 added, so the `selfRemoved` entry now arrives alongside `epochAdvanced` / `memberRemoved` for the same commit. Assert in a comment that the derived list always contains a `selfRemoved` entry on that branch.
- Record the notifications into the engine's ledger through a new `IngestContext` hook (Task 2 adds it): `ctx.recordStateNotifications(commitDigest, Number(result.newState.groupContext.epoch), notifications)`.

Derive notifications ONLY here — on the accepted-commit path. Do not derive them for a `rejected` commit, for a candidate edge inside `fork-recovery.ts`, or for a skipped input; `convergence.md` restricts notifications to accepted commits on the selected branch.
</action>

| Boundary                              | Description                                                                                                                                                                |
